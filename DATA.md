# KinCalc-EpiNet v1: Tang-dynasty epitaphs, curated kinship labels, verified test references, KinSynth, and a 40,905-person network

Companion release of the paper *Kinship Calculus as Free Supervision: Label-Efficient Construction of Genealogical Networks from Historical Biographies* (under review, 2026). Everything needed to reproduce the paper's numbers and to reuse the data for other work is here: the aligned corpus, the instruction-format splits, three item-level verified references for the test set, the cross-document benchmark, the synthetic corpora and their generators, every system's dev/test outputs, the assembled network with confidence tiers, and the code.

Licence: data and results CC BY-NC-SA 4.0 (`LICENSE-DATA.txt`, inherits the CBDB licence), code MIT (`LICENSE-CODE.txt`). Please cite the paper and the China Biographical Database (CBDB) when using the data.

## Data formats

**`data/epinet/*.jsonl`** - one epitaph per line. Fields: `id`, `code` (compilation item code), `book`, `title`, `preface`, `inscription`, `text` (full text; all spans index into `text`), `subjects` (the deceased per the source table), `ego` / `egos` (CBDB person ids recognised as the ego), `nodes` (`id`, `name`, `name_simp`, `gender` 1 male / 0 female, `birth`, `death`, `offices`, `origin`, `span` `[start, end]` or null, `in_doc`, `path_from_ego`), `edges` (`head`, `rel`, `tail`: tail is head's `rel`, CBDB kin codes). Labels come from CBDB and are incomplete (the paper estimates that the texts mention about 12% more relatives than CBDB records); recall against them is reliable, precision is not.

**`data/sft/G_*.jsonl`** - the parser's instruction data: `id`, `root` (ego name), `g_root` (ego gender), `prompt` (Chinese instruction + relation-code legend + full text), `target` (one `name | path` line per relative), `gold` (the same as a list), `maxhop`. Paths are strings over F M S D H W B Z read from the ego (FF = paternal grandfather, WF = wife's father). `unlabeled.jsonl` has the same prompt format with empty targets; `weak` holds the father's name from an independent table where available (used only as a sanity check).

**`data/kinsynth/*.jsonl`** - same format as `G_*`, generated by `code/kinsynth/gen_synth_zh.py` / `gen_synth_en.py` from random genealogies rendered with templates; labels are exact by construction. `kinsynth_zh_ego_root_6k` is the corpus used for the paper's zero-label and label-efficiency results. The English corpus uses the Re-DocRED code inventory (F, M, C child, E spouse, G sibling).

**`data/crossdoc_benchmark/crossdoc_pairs.jsonl`** - 170 pairs: `doc_a`, `doc_b`, `x` / `y` (persons occurring in only one of the two documents, with CBDB ids), `bridge` (shared person), `x_path_a`, `y_path_b`, `z_path_a`, `z_path_b`, `gold` (CBDB relation from x to y as a path), `algebra_from_gold_trees` (what the calculus derives from the gold ego trees), full texts of both documents.

**`data/verified_test/`** - `candidates/1_测试集候选.csv` lists the 620 contested test candidates (serial number, document, ego, candidate name, name variants, path, gloss, text snippet) and `0_测试集原文.csv` the full texts; `2_`-`5_` are the cross-document, correction, completion and network-edge-sample tables. `verdicts/t1_expert.tsv`, `t1_ai.tsv`, `t1_consensus.tsv` give one verdict per serial number (`对` correct, `名字有误` correct person with imprecise name, `错` wrong relation, `无此人` person not in text, `无法判断` undecidable), a corrected code where given, and a note. The expert additionally judged the 358 unanimous label items (`expert_workbook.xlsx`, sheet 1, serials 621-978). The consensus file keeps an item's verdict only where expert and AI agree (155 disagreements become undecidable). The paper reports every test number under all three references; no single annotator is treated as ground truth.

**`data/network/`** - `nodes.csv`: `node`, `name`, `n_docs`, `docs`. `edges.csv`: `head`, `rel`, `tail`, `kind` (`ego_path`: ego -> relative with the full path; `primitive`: one-step edges unrolled from paths), `tier` (`L` curated or completed label, `P` parser prediction on labelled dev/test documents, `A`-`D` re-rooting-agreement tiers for edges inferred from unlabelled epitaphs; the paper estimates tier A at about 94-99% precision and tier D at 75-76%), `n_docs`, `source_docs`. `N2_marriage.json` holds the great-clan intermarriage counts behind the paper's application figure.

**`results/predictions/<system>/pred_{dev,test}.jsonl`** - `{id, pred: {name: path}}` per document. System names follow the paper: `G` baseline parser, `JOINT` + English joint training, `Aall` + KB completion, `Ref2` + completion and correction, `STcons` + consistency-selected self-training, `SYN_full` + KinSynth pre-training, `FULL_s0` all three combined, `U_apiall` label-free pipeline, `SYN_noroot` zero-label KinSynth parser, `G_1p` / `SYN_1p` / `G_10pct` / `SYN_10pct` label-fraction runs, `APIZS` / `APIFS` zero- and 3-shot DeepSeek-V4-Flash, `QBASE` untuned Qwen2.5-7B, `G_llama` / `Aall_llama` Llama-3-8B, `TAG2_s0` discriminative token-tagging baseline.

## Reproducing the paper

1. Alignment: `code/alignment_pipeline/` (`数据处理说明.md` documents each step; needs the CBDB SQLite dump, downloaded by `step0_download_cbdb.py`).
2. Parser data: `code/parser/build_sft_data.py` (EpiNet -> G format). Training / inference: `train_lora.py`, `infer_eval.py` (Qwen2.5-7B-Instruct + LoRA r = 16, 3 epochs, lr 1e-4; one 24 GB GPU). KinSynth pre-training: train on `data/kinsynth/kinsynth_zh_ego_root_6k.jsonl` for 1.5 epochs, then fine-tune with `--init`.
3. KB co-refinement: `refine_labels.py` (2-fold cross-fitting, re-rooting tiers, completed labels). Self-training: `make_st.py`, `pseudo_label.py`. Confidence signals: `A1_consistency_signal.py`, `conf_baselines.py`.
4. Evaluation: `metrics_v3.py` / `metrics_v4_ci.py` with `T1=t1_expert.tsv` (or `t1.tsv`, `t1_consensus.tsv`) select the reference; `silver_judge.py` runs the pooled adjudication (needs `LLM_API_KEY`).
5. Cross-document inference: `code/crossdoc/crossdoc_infer.py`. Network: `N1_build_network.py`, `N2_marriage.py`.
6. Discriminative baseline: `docre_tag.py`. English: `build_redocred_kin.py` converts the Re-DocRED kinship subset (Re-DocRED itself is not redistributed here).

Paths in the scripts assume the original project layout (`实验/M_模型/sft`, `runs/`); set them to the `data/` and `results/` folders of this package.

## Provenance and ethics

Epitaph texts are transcriptions of Tang-dynasty (618-907) stone inscriptions following the compilation *Tangdai Muzhi Huibian* (Zhou Shaoliang, ed., 1992); the inscriptions are public-domain historical works. Kin labels and person identifiers come from the China Biographical Database (CBDB), CC BY-NC-SA 4.0. All persons are historical (deceased for over a millennium); no living individuals are described. The item-level verification was done first by an AI assistant and then independently by a domain expert; the two sets of verdicts are released separately, together with their consensus, so that users can choose or combine them.
