## 1. 原始数据

### 1.1 我方唐墓志表 `0_墓志数据/tang_0915_epitaphs.xlsx`

- 10,201 行,41 列。**每行一个墓主**,不是每行一篇墓志:合葬墓(夫妻/父子同志)一人一行,原文重复。
- 关键列:`编号`(不唯一,有 nan)、`姓名`、`性别`、`去世年`、`原文`、`父亲`、`祖父`、`曾祖父`、各自官职、`入仕渠道`、`籍贯_大区` 等。
- `原文` 的来源不止一种,格式不统一。其中 **3,773 行**是《唐代墓志汇编》(周绍良,上海古籍 1992)的录文格式:

```
开元０７６                                   ← 第一行:年号 + 全角三位序号 = 汇编编号
     【盖】失。                              ← 志盖文字;"失"= 盖佚
     【志文】                                ← 之后是志文
     大唐弘道观主故三洞法师侯尊志文          ← 志题(通常单独一行)
     尊师俗姓侯氏，讳敬忠，郑州管城人也。…   ← 序文,按书页硬换行,每行前有缩进
 …铭曰：                                    ← 铭文起点
     玉碎兮珠焚，…
```

其余 6,428 行来自其他集子(《全唐文补遗》、各省新出土墓志等),没有汇编编号,本次不进入训练集。

### 1.2 CBDB `1_史学家人工关系库/CBDB/cbdb_20260926.sqlite3`

哈佛/北大/中研院《中国历代人物传记资料库》,2026-09-26 版,SQLite 587 MB。用到的表:

| 表 | 用途 | 关键字段 |
|---|---|---|
| `BIOG_MAIN` | 人物基本信息 | `c_personid`, `c_name_chn`(繁), `c_female`(1 女), `c_birthyear`, `c_deathyear`, `c_dy`(6 = 唐) |
| `BIOG_SOURCE_DATA` | 人物的资料出处 | `c_textid`(32038 = 唐代墓誌匯編, 32039 = 續集), `c_pages`(**汇编编号**,如 `Kaiyuan 76`、`(XJ)Kaiyuan 76`) |
| `KIN_DATA` + `KINSHIP_CODES` | 亲属边 | `c_personid`(head), `c_kin_id`(tail), `c_kinrel`(路径码,如 F/FF/WF/DH;语义 **tail 是 head 的 rel**) |
| `POSTED_TO_OFFICE_DATA` + `OFFICE_CODES` | 任官 | 官名 |
| `BIOG_ADDR_DATA` + `ADDR_CODES` | 籍贯(`c_addr_type=1`) | 地名 |
| `NIAN_HAO` | 年号表 | 拼音 ↔ 汉字,用于把 `Kaiyuan` 翻成 `开元` |

唐代部分:57,477 人;亲属边 89,228 条,其中来源为《汇编》22,665 条、《续集》10,657 条、Tackett 库 48,846 条(CBDB 把 Tackett 1.0 整库合并进来了,**这部分没有汇编编号**)。

### 1.3 Tackett TBDB 1.5 `1_史学家人工关系库/Tackett_TBDB/tbdb015_v1.5.accdb`

伯克利 Nicolas Tackett《唐五代人物传记与社会网络资料库》,39,204 人、39,180 条关系、5,608 方墓志、5,325 条姻亲、3,536 条撰书者。没有汇编编号,只能按姓名 + 年份对齐(step5)。

## 2. 各步骤详解

### step0 下载

- `step0_download_cbdb.py`:读 Hugging Face `cbdb/cbdb-sqlite` 的 `latest.json` → 下载 zip → sha256 校验 → 解压。文件名随版本变,改 `common.CBDB_SQLITE`。
- `step0_download_tackett.ps1`(PowerShell):Google Drive 大文件要先请求一次拿 `uuid` 再带 `confirm=t` 下载;下载后用 Windows 自带 ACE OLEDB 驱动把 Access 的每张表导成 UTF-8 CSV(`tbdb015_csv/`)。

### step1 抽《汇编》语料并拆块 `step1_extract_huibian_corpus.py`

**判定**:原文第一行匹配 `年号(2–4 汉字) + 数字(1–4 位, 全角或半角)`,且年号在 CBDB `NIAN_HAO` 的年号集合里。命中 3,773 行。

**拆块规则**:

| 块 | 规则 |
|---|---|
| `code` | 年号转简体 + 序号去前导零:`开元０７６` → `开元76` |
| `cover` | `【盖】` 到 `【志文】` 之间,去空白;空则 None |
| `title` | `【志文】` 后第一个非空行,若 ≤40 字、含 志/铭/墓/记/碣/塔、且无逗号句号 → 作志题 |
| `text` | 志题之后所有行 `strip` 后直接拼接,再删掉所有半角/全角空格。**后续所有 span 偏移都基于这个字符串** |
| `preface` / `inscription` | 在 `text` 里找最后一个 `铭曰 / 其词曰 / 其辞曰 / 词曰 / 辞曰 / 铭云 / 系之铭曰`,之前为序,之后为铭;找不到则 inscription=None |

**去重**:键 = `(code, text 前 200 字)`。同一篇原文在表里多次出现(合葬一人一行,或重复录入)只保留一篇,各行的墓主并入 `subjects` 列表。

**结果**:3,773 行 → **3,323 篇**,其中多墓主 445 篇;有志题 2,927,有铭文 2,796。输出 `汇编文本_分块.jsonl`。

**已知问题**:志题行若因排版换行把撰者衔名带在后面(如"…沈府君墓志铭 季弟衮海节度判官…"),会一起进 `title`;`text` 开头可能残留撰者名的后半段。

### step2 映射到 CBDB `step2_map_cbdb.py`

**编号翻译**:CBDB `c_pages` 形如 `Kaiyuan 383` / `(XJ)Huichang11`(XJ = 续集),正则 `\(?(XJ)?\)?\s*([A-Za-z]+)\s*(\d+)`,拼音查 `NIAN_HAO` 得汉字年号。27,139 条出处记录中 26,651 条可解析。

**正编 / 续集判定**:两本书各自从 1 编号,同一 `开元140` 可能两本都有。对每篇原文,分别取两本书在该编号下登记的人物,数**有多少人名出现在本篇原文里**(`name_in_text`,见 §3),多者为本篇所属;都为 0 → 未映射。

**结果**:3,323 篇 → 正编 2,745、续集 5、未映射 573(编号不在 CBDB 213 篇;编号在但人名对不上 360 篇)。
反向:CBDB 录过而我方没有原文的:正编 349 号、续集 170 号 → `CBDB有_我方缺_编号清单.csv`(附人物名,可据此补文本)。

**为什么续集只有 5 篇**:我方原文里基本没有续集的录文(续集特征 `№编号`、`录自《…》` 零命中);这 5 篇是撞号后续集人名恰好命中。

### step3 构造训练样本 `step3_build_epinet.py`

对每篇映射成功的原文:

1. **节点(a)**:CBDB 在该书该编号下登记的全部人物(`in_doc=True`),带性别、生卒年、官职列表、籍贯列表。
2. **边**:节点(a)中每个人物在 `KIN_DATA` 的全部出边 `(head, rel, tail)`。
3. **节点(b)**:边的 tail 若不在(a)中,也加入(`in_doc=False`)——这些是从别的墓志/史书录入的亲属,通常不在本篇原文里。
4. **墓主 ego**:节点(a)中姓名(繁)等于我方表 `subjects` 里任一姓名者;没有则找志题里出现的人名;再没有 ego=None(样本仍保留,但没有相对路径)。认出 2,299 / 2,750 = 83.6%。认不出的主要是女性(`X氏`)和异体字。
5. **相对墓主路径 `path_from_ego`**:从 ego 出发 BFS ≤5 跳。
   - 沿出边:路径直接拼接,ego —F→ X —F→ Y ⇒ Y = `FF`。
   - 出边不够时用入边反转:X —S→ ego(ego 是 X 的子)⇒ X 是 ego 的 F 或 M,看 X 性别。多步反转时中间节点性别由字母本身决定(F/S/H/B 男,M/D/W/Z 女),见 `common.inverse_path`。含 `G-n / K+n / U / 数字` 等非基本码的边不反转。CBDB 86% 的边本来就有反向边,反转只是补漏。
   - 化简 `normalize_path`:`FS→B`(父之子 = 兄弟)、`FFS→FB`(祖之子 = 伯叔)、`FD→Z`、`MS→B`,循环到不变。
6. **span**:`name_in_text`(§3)在简体 `text` 里定位人名。本篇登记节点定位率 69.5%;`in_doc=False` 节点 6.2%(符合预期)。
7. **划分**:`md5(code) % 10`:0–7 train、8 dev、9 test。同一编号永远在同一份里。

**结果**:2,750 篇 → train 2,237 / dev 286 / test 227;节点 22,777(本篇登记 15,430);边 37,002(每篇 13.5);有相对路径的节点 16,255,路径 829 种。

### step4 统计与校验 `step4_stats_and_checks.py`

- 路径分布 top:S 2,622、F 1,955、FF 1,819、FFF 1,263、W 1,020、H 576、FB 451、B 415、WF 362、FFFF 343、FFB 335、SS 293、DH 259、D 193、M 153……
- 边类型 241 种,top:S 8,938、F 7,003、FF 2,423、SS 2,342、W 2,066、H 1,813、FFF 1,586、SSS 1,499、D 1,155、DH 1,131、WF 1,025、M 1,024。
- **交叉校验**:认出 ego 的篇里,我方表的 `父亲`/`祖父` 与 CBDB 路径 F/FF 的人名比对(允许繁简、去姓):3,456 对,一致 **85.9%**。不一致的看例子多是异体/校勘(程鉴 vs 程鑒、刘伸 vs 劉神)、写法(谭亮齐 vs 譚亮、秦张亮 vs 秦亮)、我方表本身残缺(王□),少数是真错(贞观34 对到了另一人的亲属)——这些要留到人工复核。
- 打印一篇样本到 `统计.txt` 末尾供肉眼核对。

### step5(可选)Tackett 对齐 `step5_align_tackett.py`

`People` 的 姓+名(转繁)= 我方 `姓名`(转繁),且 `Epitaphs.Burial date` 与我方 `去世年` 相差 ≤3 年。得 1,768 篇,关系 + 姻亲 + 撰者 8,457 条(每篇 4.8)。输出 `Tackett_TBDB/对齐数据集/tbdb_text2graph.json`。Tackett 的价值是 CBDB 没有的:姻亲郡望、幕僚(Cl)、撰/书者及其与墓主关系。

## 3. 公共规则(`common.py`)

| 函数 | 规则 |
|---|---|
| `clean_name` | 去空白、间隔号,去掉 CBDB 人名后括注:`李氏(崔夐妻)` → `李氏` |
| `t2s / t2t` | zhconv 繁简互转;所有比对都在同一字形下做 |
| `name_in_text(name, text_simp)` | 依次试:全名 → 名(≥2 字)→ 单字名且前 4 字内有 讳/父/祖/考/妣/子/女/兄/弟/妻/夫人/字。`X氏`、`X某` 不定位 |
| `code_from_text_head` | 我方原文首行 → 编号 |
| `code_from_cbdb_pages` | CBDB 页码 → 编号 |
| `base_steps / inverse_path / normalize_path` | 亲属路径拆步、反转、化简 |

## 4. 最终数据格式 `data/训练集/epinet_v0/*.jsonl`

每行一篇:

```json
{
 "id": "大中140_8490", "rid": 8490, "编号": "…", "code": "大中140", "book": "正编",
 "cover": "失。", "title": "唐故承奉郎守大理司直沈府君墓志铭…",
 "preface": "…", "inscription": "…", "text": "奉佐黄撰沈氏之先，左传详矣。…",
 "subjects": [{"rid": 8490, "name": "沈中黄", "gender": "男", "death_year": 855.0}],
 "ego": 141734, "egos": [141734],
 "nodes": [
   {"id": 141734, "name": "沈中黃", "name_simp": "沈中黄", "gender": 1, "birth": null, "death": 855,
    "offices": [], "origin": [], "span": [186, 188], "in_doc": true, "path_from_ego": "EGO"},
   {"id": …, "name": "沈竦", "gender": 1, "offices": ["大理正"], "span": [152, 153], "in_doc": true, "path_from_ego": "F"},
   {"id": …, "name": "呂溫", "offices": ["副使", "戶部員外郎"], "span": [623, 624], "in_doc": true, "path_from_ego": "WF"},
   …
 ],
 "edges": [{"head": 141734, "rel": "F", "tail": …}, {"head": 141734, "rel": "WF", "tail": …}, …]
}
```

- `span` 是 `[start, end)` 字符偏移,基于 `text`(简体化后长度不变,偏移可直接用于 `text`)。
- `edges.rel` 是 CBDB 原始亲属码(**tail 是 head 的 rel**),`path_from_ego` 是相对墓主的化简路径,两者并存:前者训练三元组抽取,后者训练 ego 中心抽取。

## 5. 已知噪声与处理建议

| 问题 | 来源 | 建议 |
|---|---|---|
| CBDB 重复人物(沈棲重 / 沈栖重 两个 id;呂溫 两个 id) | CBDB 自身 | 训练前按 `name_simp + path_from_ego` 去重 |
| 约 14% 人名与我方表写法不一致 | 异体字、校勘、录入差异 | 评估时用宽松匹配;人工复核测试集 |
| CBDB 未必录全文中所有人物 | 录入范围 | 查全率可信,查准率需人工复核(测试集 227 篇建议全部复核) |
| 女性多为 `X氏(某妻)`,无 span | 史料本身 | 作为"无 span 节点"单独评估或忽略 |
| 志题吞进撰者衔名 | 排版换行 | 需要时用"撰/书"切分 |
| 少数编号撞号映射错人(如贞观34) | 正编/续集/异文 | 人名命中数低(≤1)的篇可标为低置信 |
| 573 篇未映射、CBDB 有而我方缺 519 号 | 覆盖差 | 前者可用 T1 式 LLM 弱标注;后者需补《汇编》文本 |
